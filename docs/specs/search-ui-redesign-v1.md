# 銘柄検索画面の再構築仕様

更新日2026年11月12日。12項目の選択回答と費用初期値の変更を反映した。状態は実装・検算・mainへのpushを承認済み。

## 確定した構成

画面は銘柄検索・銘柄詳細・検証結果の3つとする。日本語表示を基本とし、入口の共通計算式と検証時の条件定義を使用する。運用検討は日足のスイングを中心とする。検証成績は検証結果画面へ集約する。

## 銘柄検索

- TradingView添付版、Anti 3/10適応版、Anti 7/4/10版、初期試作版、ミネルヴィニ派生版、RSI2、RSI14の7入口を用意する。
- 複数選択とOR／AND切替を用意し、初期状態はTradingView添付版のみ選択・ORとする。
- 各入口を同じ判定日の日足で評価し、入口別の成立状況を表示する。
- 対象は東証普通株全体、国内上場ETF全体、コード指定から選択できる。初期状態は東証普通株。
- 普通株・ETFとも20営業日平均売買代金10億円以上、金額順最大100銘柄を初期値とする。金額・件数は変更可能とする。
- 追加指示により流動性条件をON／OFFできるようにする。初期はON。OFF時は売買代金の下限・上位件数による絞り込みを外し、選択対象全体へ入口判定を適用する。平均売買代金が未計算の銘柄も、入口の必要データがあれば判定対象とする。購入予算のON／OFFは独立とする。
- 終値×出来高を用いる場合は概算と表示する。購入額と売買代金は当日の取引価格単位で計算し、指標に使用した価格調整方法を表示する。
- 日足ATR14は参考表示とする。
- 1銘柄あたりの任意予算を設定でき、初期状態の予算絞り込みはOFFとする。
- 普通株は100株単位、ETFは銘柄ごとの売買単位で予算内株数・概算購入額を計算する。単位未確認は確認待ちとする。
- 上場一覧の基準日・取得日、絞り込み前後の件数、判定日・価格取得日時を表示する。
- 通常は前営業日までを使用し、当日値の利用は毎回手動選択とする。過去の判定日も指定できる。
- 当日値は配信時点の暫定値として表示する。当日選択を保存済み設定から自動復元する扱いは採用せず、当該実行時の選択を必要とする。
- 入口は検証時のパラメーターを初期設定とし、変更は詳細設定に配置する。
- 出口はA〜Dから選択し、初期状態はA。初期損切りは3／5／8／10／12%から選択し、初期状態は10%。
- 結果には銘柄名・コード・成立状況・判定日・株価・売買単位・概算購入額・平均売買代金・ATRを表示する。

## 更新・保存

検索時は保存済みデータを確認して必要な差分を取得する。初回などの全市場データ準備は明示ボタンから開始し、進捗・取得失敗・更新日時を表示する。画面を開いた際は直近の保存結果を表示する。

検索設定は名前を付けて利用端末のブラウザー内へ保存する。詳細画面から戻る際は条件と一覧位置を保持する。初期全体準備・再取得と条件判定の処理状態を画面に表示する。

## 銘柄詳細と概算費用

チャート、指標、条件ごとの合否・数値を表示する。想定購入価格と基準日を指定し、購入株数・概算費用・損切り時の想定損益と出口水準を表示する。

手数料無料の適用を前提とするSBI証券向け初期設定は、片道手数料0%・成行スリッページ0.05%。両方を変更可能にする。スリッページは実測値に基づかない試算仮定であり、税引前の金額を表示する。ギャップや急変により想定損失額を超える場合があることを示す。

日足検証の出口定義を継承する。

| 出口 | 表示する運用条件 |
| --- | --- |
| A | 初期損切りを固定し、保有期限を設けない |
| B | 初期損切りと手法別の売却条件。TradingView・Anti・初期試作版は売りシグナル、RSI系はRSI50以上、ミネルヴィニ派生版は観測高値から10%のトレーリング |
| C | 終値の到達段階で損切りを切り上げ、利確は購入価格から24%上昇の固定水準 |
| D | 終値の到達段階で損切りと利確の双方を切り上げる |

C/Dは既存検証の基準幅である購入価格の8%を使用し、初期利確はその3倍。初期損切り率と基準幅はそれぞれ表示する。段階更新後の価格出口は翌営業日から有効とする。Bの確定売却シグナルも翌営業日寄付の条件として表示する。

実装提案として、複数入口を選択した場合のBは入口ごとの売却条件を表示する。想定購入日以後の履歴がある場合は共有の出口関数で更新経路を計算し、想定購入条件に基づく参考水準であることを表示する。

## 検証結果

保存済み日足560条件を参照し、2016〜2020年と2021〜2025年、個別株・ETFを対応付ける。期末資産・年率・最大ドローダウン・取引数・1取引平均純損益・資産推移とオルカン比較を表示する。初期資金1,000万円、費用込み10万円の仮想端数購入など、実施条件を併記する。

2016〜2020年のオルカンは実ファンド設定前を含む状態を表示する。既存検証は片道手数料0.1%・成行スリッページ0.05%の税引前成績。現在の費用設定との差を表示する。

入口パラメーター変更、複数入口のOR／AND、流動性・予算による絞り込み、実売買単位への変更には、検証条件との差と変更後未検証の表示を付ける。条件が異なる場合は参照元の入口・出口・損切り・期間・資産区分を明示する。

主要集計と必要な資産推移をアプリから参照できる形で同梱し、別端末での起動でも表示できる構成を実装範囲として提案する。今回の範囲は保存済み結果の表示と検索画面の作成であり、新しい条件のバックテスト開始は別途承認を得る。

## 表示と未取得情報の扱い

PCは結果一覧表、スマホはカード表示を基本とし、どちらからも同じ銘柄詳細へ移動できる。銘柄検索を初期画面とし、条件変更後は保存結果の実行条件と画面設定の差を表示する。

実装提案として、判定は成立・不成立・判定不可を扱う。必要価格・RS参照・準備本数が不足する場合は理由付き判定不可とする。ORは成立が1つあれば成立、全入口が不成立なら不成立、それ以外は判定不可とする。ANDは不成立が1つあれば不成立、全入口が成立なら成立、それ以外は判定不可とする。

コード指定にも表示中の流動性・予算条件を適用し、利用者が変更できる構成を提案する。初期ソートは平均売買代金の降順・同額はコード順とする。過去日検索では参照する上場一覧の基準日を表示し、当時の対象一覧に関する制約を示す。

価格・気配・売買停止状態は確認できた取得日時と判定状態を表示する。未取得の気配・市場状態は確認待ちとする。
