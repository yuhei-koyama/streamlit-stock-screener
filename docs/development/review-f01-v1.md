# F01。全市場処理の入力世代混在防止

2026年11月7日。ユーザーは1件目の修正案に「承認する（推奨）」と回答。対象はレビューF01の再開・集計時の依存入力照合と回帰テスト。

## 確定した修正範囲

- 銘柄価格、RS参照1306.T、コード、カレンダー規則をフェーズごとに記録する。
- 入力世代が異なる場合は再開を停止し、新しい作業先での再計算を必要とする。
- entry/exitsを追加しても、既存フェーズの依存入力と成果物ハッシュを保持する。
- 集計時もフェーズ記録と現在の入力・実行条件を照合する。

## 実装

`stock_screener.market_research`へ共通の依存照合とフェーズ記録検証を追加した。処理対象へ書き込む前に、既存の全結果の依存情報と成果物を確認する。計算に使う価格CSVは、同じ読み込みバイト列でハッシュ照合とCSV読込を行う。

status.jsonの`phase_records.entry`と`phase_records.exits`に、それぞれ依存記録と当該フェーズのZIP・集計CSV・休場日除外原票のハッシュを保存する。トップレベルの従来項目は既存利用者向けに保持し、フェーズ記録を検証の根拠とする。

フェーズ別記録を持たない旧形式は、RS参照等の過去の世代を安全に復元できないため自動移行しない。新しい作業先での再計算を案内する。

## 検証条件

- 同一条件でentryからexitsへ再開し、entryの記録を保持する。
- 銘柄価格と取得メタデータの両方を更新しても、既存結果の新しい世代への付け替えを拒否する。
- 銘柄自身の価格が同じでも、RS参照の変更を検出する。
- コードまたはカレンダー規則の変更を検出する。
- フェーズ記録のない旧形式と、改変された既存成果物を拒否する。
- 拒否時に他銘柄の次フェーズを新規出力せず、既存の成果物を保持する。

検証は合成データと既存の全自動テストを使用する。実市場の成績の再計算とは区分する。
