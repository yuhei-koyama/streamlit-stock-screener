# テスト方針・品質保証

作成日: 2026-11-05 / 版: 1.0-draft / 状態: **高水準方針・未承認**

本書は仕様承認前のテスト方針である。期待値、fixture、具体的なテストケース、採否基準を含む詳細テスト設計は仕様承認後に作成する。

## 1. 基本方針

- 各テストを要求ID、戦略定義版、データ契約、約定規則へ対応付ける。
- 実データだけに依存せず、手計算できる小さな合成データを中心に正しさを証明する。
- 承認済み指標の式と状態遷移を、手計算fixtureと境界テストで固定する。
- 数学的正しさ、時系列因果性、会計整合性、再現性をUIより先に確認する。
- データ供給元の障害や訂正を、戦略不成立と区別して報告する。
- バックテスト結果の良さをテスト合格条件にしない。正しい処理で不振な結果が出ることを受け入れる。

## 2. テスト層

| 層 | 主な検証 |
| --- | --- |
| データ契約 | スキーマ、型、時刻、重複、欠損、調整係数、銘柄有効期間 |
| 指標単体 | 手計算系列、初期値、同値、欠損、ウォームアップ、SMA/EMA差 |
| 戦略単体 | 成立/不成立、境界、不足、選別と入口/出口、理由コード |
| 因果性 | 将来行を変更・追加しても過去のシグナルと約定が不変 |
| 約定 | 翌日化、休日、ギャップ、停止、値幅、単位、資金不足、コスト |
| 企業行動 | 分割、併合、配当、ETF分配金、上場・廃止、二重計上防止 |
| ポートフォリオ | 同時候補、順位、上限、丸め、追加購入、現金、再投資 |
| 会計 | 現金＋時価等＝純資産、取引・企業行動前後の保存則 |
| 指標集計 | CAGR、TWR、XIRR、DD、Sharpe、Sortino、PF等の独立検算 |
| ベンチマーク | 同じ期間・入出金・円建て・再投資・費用の適用 |
| 統合回帰 | 固定データからシグナル、取引、資産、指標の全成果物を照合 |
| UI | 個別株/ETF別、警告、データ品質、PC/スマートフォン表示 |
| 性能 | 想定銘柄数・期間の時間/メモリ。高速化前後で結果が同一 |

## 3. 重要な具体的性質

### 因果性
- t以後の価格を異常値へ変更してもtより前の結果が変わらない。
- t日に新規上場する銘柄がt以前のRS順位へ入らない。
- 後日訂正された財務値を公表前に使わない。
- t日終値シグナルがt日終値で約定しない標準モデルを確認する。

### 企業行動・配当
- 2分割で経済価値が変わらず、数量2倍・単価半分になる。
- 配当調整済み価格と現金配当を同時に使って二重利益を作らない。
- ETF分配金と個別株配当を同じ項目へ混同しない。
- 廃止前後に注文・評価が継続しない。

### 日足内の曖昧さ
- 同一バーでストップと利確に到達する合成データを用意し、承認した優先規則どおりになる。
- 始値がストップを飛び越えた場合、ストップ価格で都合よく約定しない。

### 会計
- コスト0・企業行動なしなら、売買前後の現金＋時価の変化が価格変化だけと一致する。
- 手数料とスリッページを増やした結果が、同じ約定列でコスト0より良くならない。
- 資金不足、売買単位丸め、部分約定後も現金が不正に負にならない。

## 4. 独立検算

- 代表的な指標と取引を表計算または非常に単純な参照実装で検算する。
- 本実装と同じ補助関数を参照実装で再利用しない。
- LBR 3/10と7/4/10ストキャスについて、少数の固定OHLC系列から手計算した期待値と最初の有効位置を保存する。
- 評価指標は小さな日次資産系列と取引表を手計算し、丸め前の値で照合する。

## 5. 再現性

同一コード版、同一データハッシュ、同一設定、同一乱数シードから、次が一致することを確認する。

- シグナルと理由
- 注文・約定・拒否
- 日次現金・保有・純資産
- 指標値
- 結果成果物の内容ハッシュ（実行時刻等の可変メタデータは除外）

## 6. 統計・研究上の品質保証

- IS/OOS境界を事前固定し、OOS閲覧後の修正履歴を残す。
- 試した全戦略・全パラメータ・全出口を登録する。
- OOSの取引数や期間が少なければ「不十分」と判定する。閾値は未決定。
- パラメータ近傍で結果が急変しないか、コスト・スリッページのストレスで優位性が残るか確認する。
- 個別株/ETF、年度、相場局面の安定性を確認するが、事後的に好成績区間だけを採用しない。
- 可能ならウォークフォワードで再学習/選定と次区間評価を分離する。
- 区間推定を採用する場合、固定乱数シードで再現できること、時系列用の再標本化単位を守ること、小さな既知系列で分位点・境界を検算する。

## 7. UI・端末確認

PCとiPhoneについて、少なくとも次を確認対象候補とする。

- 戦略・資産クラス・期間の選択
- データ品質と警告の視認
- 主要指標と資産曲線
- 個別株/ETFの切替
- 詳細表の閲覧またはダウンロード
- 画面回転、狭い幅、長い処理の進捗・再読込

対象OS・ブラウザー・端末、CSVをiPhone必須とするかは未決定。

## 8. 品質ゲート案

正式な戦略比較へ進む前に、次を満たすことを提案する。

1. 重要要求と詳細テストケースのトレーサビリティが100%。
2. 指標・因果性・約定・企業行動・会計の必須テストが全合格。
3. 未解決のデータ欠損と既知バイアスが結果に自動表示される。
4. 代表ケースを独立検算済み。
5. 同一入力で再現可能。
6. OOSを実行する前に戦略版・期間・評価指標を凍結。

合格率や許容誤差、性能目標、最低OOS期間・取引数は仕様承認後の詳細テスト設計で決める。
