# バックテストエンジン設計

作成日: 2026-11-05 / 版: 1.0-draft / 状態: **提案・未承認**

## 1. 設計原則

- 日付のベクトル演算だけで売買損益を作らず、注文、約定、現金、保有を時系列で処理するイベント駆動型とする。
- 戦略判定と約定を分離する。戦略は希望する売買を返し、約定・資金制約・売買単位は共通エンジンが処理する。
- 1銘柄ごとのシグナル精度と、複数銘柄を持つ実際のポートフォリオ成績を別々に評価する。
- 日ごとの状態と全イベントを保存し、最終指標から元の注文・シグナルへ追跡できるようにする。

## 2. 日足処理順

### 提案する標準モデル
終値を使う戦略は、t日引け確定後にシグナルを生成し、最短でt+1営業日の始値に約定する。これは承認事項であり、戦略原典が別の注文方法を指定する場合は別Execution Policyとして扱う。

```text
t日開始前: その時点までに有効な注文と取引可否を確認
t日始値:   始値対象の注文を約定、ギャップとコストを反映
t日日中:   日足で判定可能なストップ等を規則に従って処理
t日終了:   配当・企業行動・時価評価・会計照合
t日引後:   t日までの確定データだけで指標とシグナルを計算
            → t+1日以降に有効な注文候補を生成
```

各シグナルには `decision_timestamp`、`data_cutoff_timestamp`、`earliest_execution_timestamp` を保存する。取引所休場日、銘柄ごとの売買停止・上場期間を確認して次の取引可能日を決める。

## 3. ルックアヘッド防止

- `as_of` より後の行を戦略へ渡さない。単なる最終行シフトだけに依存しない。
- ブレイクアウトの過去高値・安値窓に判定当日を含めるかを明示し、通常は当日より前で閉じる。
- 横断面RS順位は、その日に存在し、その時点で利用可能な銘柄だけで計算する。
- 将来追加する財務情報は決算期末日ではなく公表日時以降に利用する。
- 欠損を後日の値で補完しない。企業行動の訂正・遡及更新はデータ版として記録する。
- 将来データを変更しても過去時点のシグナル・注文・約定が変わらない因果性テストを必須にする。

## 4. 過去時点の母集団

各日について、上場済みかつ未廃止で対象資産クラスの銘柄集合を作る。現行上場銘柄だけで過去を検証した結果は `survivorship_biased=true` とし、正式比較ランキングへ入れない案を提案する。

上場廃止では、最終取引日、売買停止、交換・現金対価等が得られる場合は実際のイベントを処理する。得られない場合に価格を勝手にゼロ・最終値固定にせず、採用する保守的規則と影響銘柄を承認事項にする。

## 5. 価格、企業行動、配当

### 提案する会計分離
- シグナル計算用系列: 連続性を保つ調整系列を使う場合、調整方式と利用可能時点を記録。
- 約定用系列: 実際に売買可能だった未調整OHLCを使用。
- ポートフォリオ会計: 分割・併合で数量/単価を調整し、配当・分配金は権利と支払規則に従って現金化。

調整済み終値で値上がりを反映しながら同じ配当を現金加算するなど、経済効果を二重計上しない。使用データに支払日がない場合、権利落日加算等の代替は仮定として明示する。

## 6. 約定モデル

初期の株式・ETFモデルが扱う設定:

- 注文種別: 翌日始値成行、寄付/引け、ストップ等（初期採用範囲は未決定）
- 売買単位と日付による変更、数量切捨て
- 始値ギャップ、値幅制限、売買停止、出来高0
- 手数料体系、最低手数料、消費税等
- 固定bps、片道、価格/出来高依存等のスリッページモデル
- 1日の出来高に対する最大参加率と未約定/部分約定
- 注文有効期限、キャンセル、資金不足時の減額/拒否

日足OHLCだけでは高値と安値の先後が不明である。利確と損切りが同じ日に到達する場合は、保守的順序、最悪ケース、曖昧取引として除外、より細かい足を使う、のいずれかを固定する。楽観的な順序を暗黙に選ばない。

## 7. ポートフォリオ

必須設定:

- 初期資金、外部入出金、待機現金の扱い
- 最大保有数、1銘柄上限、個別株/ETF上限
- 同日候補の順位と同順位の決定規則
- 等金額、等リスク、固定損失額、ATR/N等のサイズ方式
- 売買単位、端数、最低購入金額
- 資金不足時の拒否または数量縮小
- 同一銘柄の追加購入、部分決済、再エントリー、クールダウン
- ETFと構成資産の重複、業種・相関上限（初期に使うかは未決定）

戦略間比較では、共通の資金配分を使うケースと、タートルズ等の戦略固有サイズを使うケースを分ける。

## 8. 評価指標の定義案

以下は実装前に数式・端数・例外を承認する。

### 資産とリターン
- 日次純資産 = 現金 + 全保有の評価額 + 未収金等（採用範囲を明示）。
- 累積リターン: 外部入出金がない場合 `最終純資産 / 初期純資産 - 1`。
- CAGR: 外部入出金がない一括投資ケースで、実日数を年換算して計算。
- 積立ケース: 日次時間加重収益率（TWR）、XIRR等の資金加重収益率、最終資産額、累計入金額を併記。積立ケースの単純な最終/初期をCAGRと呼ばない。
- 年次リターン: 暦年の日次TWRを複利連鎖。初年・最終年の部分期間を明示。
- 平均取引損益: コスト控除前後、金額と投入資本比率を別表示。
- Profit Factor: 確定利益合計 / 確定損失絶対値。損失0等の境界表示を決める。

### リスク
- 最大ドローダウン: 日次純資産の過去最高値からの最大下落率。期間と回復日も保存。
- ボラティリティ: 日次TWRの標準偏差を所定の営業日数で年率化。
- Sharpe: 日次の超過収益平均 / 標準偏差を年率化。無リスク金利の系列または0%は未決定。
- Sortino: 日次収益と承認済みMARから下方偏差を計算。MARと年率化は未決定。
- 最大連敗数: 決済順の取引損益で計算。同日決済順とゼロ損益の分類を決める。

### 売買特性
- 勝率、総取引数、平均/中央値保有期間。
- 平均利益、平均損失、損益比率。
- エクスポージャー、現金比率、回転率、最大同時保有数。
- 手数料、スリッページ、税、配当の各寄与。
- データ不足・注文拒否・未約定・除外銘柄の件数。

## 9. インサンプル、アウトオブサンプル、試行管理

- 先に期間分割と評価指標を固定し、OOSを見てからパラメータを戻さない。
- 全試行の戦略版、パラメータ、データ、結果を登録し、最良結果だけを残さない。
- OOSは最終確認まで隔離する。修正後に再利用した区間は以後「未見」と呼ばない。
- 十分な期間がある場合は、過去窓で選定して次の窓を評価するウォークフォワードを行う。
- 複数戦略・多数パラメータ探索によるデータスヌーピングを、試行数、結果分布、安定性で報告する。
- 個別株とETF、相場局面、年度別に分解するが、事後的な都合のよい部分集合だけを主結果にしない。
- OOSの年率リターンを1つの値だけで示さず、年次・ウォークフォワード区間の分布を併記する。データ量が許す場合は、時系列依存を壊しにくいブロック・ブートストラップ等で収益・リスク指標の区間推定を行う。再標本化方法、ブロック長、反復数、乱数シードを保存する。
- 信頼区間やブートストラップはデータ品質、サバイバーシップバイアス、過剰探索を解消しないため、それらの品質ラベルとは別に表示する。

具体的な期間はデータ源と戦略の最長ウォームアップが決まった後に承認する。

## 10. 出力成果物

各実行で次を保存する。

- 実行マニフェストとデータ品質レポート
- 日次の現金、保有、純資産、外部入出金、ベンチマーク
- シグナル、注文、約定、拒否、取消、企業行動
- ラウンドトリップ取引と損益内訳
- 指標一式、個別株/ETF別、年度別、IS/OOS別の集計
- 使用した全パラメータと試行ID
- 警告、既知のバイアス、比較不能理由

結果画面は「データ品質」「OOSか」「コスト・税」「ベンチマーク期間」を成績より先に確認できるようにする。
