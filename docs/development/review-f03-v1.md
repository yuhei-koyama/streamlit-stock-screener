# F03。追加期間の価格補正を固定承認へ結び付ける

2026年11月7日。ユーザーは3件目の修正案に「承認する（推奨）」と回答。元データ・銘柄・日付・補正前後の値を承認済み一覧へ限定する。

## 実装と信頼の根拠

- 固定承認レコードは`artifacts/backtest/period-2016-2020-20261106-01/rounding-approval-20261107-01/approval.json`。同じディレクトリの`approved_corrections.csv`へ既承認197行をバイト列のまま保存した。この2ファイルもコードとともに共有する。
- `stock_screener.correction_approval`に承認レコードのSHA-256を固定する。レコード自身、197行CSV、元のsource/collection.json、そこに列挙された原本ファイルを照合する。
- 追加期間のprepareはフラグを指定するだけでは未知の元データを補正しない。固定承認と一致する元データから、承認された銘柄・日付・元価格・修正後価格だけを補正する。
- 対象一覧の欠損・重複、元価格の不一致、計算した補正後価格や差額の不一致、一覧外の不整合、原本変更を拒否する。従来の微小差上限も維持する。
- 補正対象の全件照合を出力作成前に完了する。承認行がなくなった場合や未処理行が残る場合も停止する。
- 休場日の承認行は元の値を照合したうえで補正不要に区分し、`skipped_approved_corrections.csv`へ保存する。
- 派生入力に承認レコード・承認一覧・除外された承認行・各ハッシュを保存する。load_datasetはこれらの承認履歴ハッシュと元コレクション・適用件数の整合を確認する。

CLIは従来の`--approve-rounding`を使用するが、このフラグを新しい行や再取得データの承認として解釈しない。別の元データ・別の一覧を扱う場合は個別の確認・承認と固定レコードの追加が必要。
