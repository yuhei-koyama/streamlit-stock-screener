## テスト設計

- 既知の行で高値が終値を下回るケースと安値が終値を上回るケースを用意し、OHLC最大・最小への補正を確認する。
- 原本と補正元のハッシュを保持し、補正後の再読込でも始値・終値・出来高・日付が完全に一致することを確認する。
- 判定系列と約定系列の一致、分割1・配当0・仮想1株という探索入力の契約を確認する。
- 指定外の不整合、指定一覧の欠落・重複、ハッシュ不一致、非有限値・非正価格で停止することを確認する。
- 既存入力の読み込みと厳密モードの品質ゲートを回帰確認する。
- 実データで63行だけが補正され、分類が微小差56行と実質差7行になることを確認する。

## 実装計画

1. 既存入力ハッシュと承認対象行の一覧を照合するオフライン補正処理を追加する。
2. 新しい派生入力へ補正履歴・処理版・入力ハッシュを保存する。浮動小数点は往復精度を保持して読み込む。
3. CLIから補正処理を呼び出せるようにする。
4. 自動テスト後、取得済みYahoo Financeデータへ適用し、独立評価14条件を実行する。
5. 取引の元本・約定日・損益率の整合性、件数と年別・銘柄別集計の一致、ZIPの内容を検証し日本語報告へ記録する。
