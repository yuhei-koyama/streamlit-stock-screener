# 日本株・国内ETFのデータソース調査

調査日: 2026-11-05 / 版: 1.0-draft / 状態: **調査結果＋提案・未承認**

## 1. 結論

無料だけで「長期の日足、配当・ETF分配金、企業行動、過去時点の全銘柄母集団、上場廃止、売買単位履歴」を一貫して満たすデータ源は確認できなかった。無料構成は戦略開発と探索には使えるが、長期の正式評価には重大な限界が残る。

データ供給元を差し替え可能にし、結果を次の品質区分で表示する案を提案する。

- `exploratory`: 無料データ中心。既知のバイアスを警告し、投資判断用の確証としない。
- `validated_with_limits`: 過去母集団・企業行動等の主要条件を満たすが、一部制約あり。
- `formal_candidate`: 承認済みデータ、約定、会計、OOSを満たす。将来成果を保証する意味ではない。

## 3. J-Quantsで確認できた制約

### 確認事項
- Freeの上場銘柄一覧・株価四本値は、12週間前から2年12週間前までの範囲で、APIアクセスのみ。
- Freeの基本レート制限は5リクエスト/分。
- 上場廃止銘柄も、格納期間内かつ上場中の日付・期間を指定すれば取得できる。
- 銘柄マスターの商品区分を使って株式・ETF等を識別できるため、初期対象の分離に利用できる候補である。
- ただし上場・廃止日の一覧、廃止銘柄一覧、売買単位とその変更履歴はJ-Quants APIから完結して得られない。
- 分割・併合等の調整済み株価は提供されるが、現金配当データはPremium範囲であり、無料OHLCだけで配当込みポートフォリオ会計はできない。
- 配信は日次でリアルタイムではない。対象銘柄数は固定値ではなく、各時点の東証上場状態と商品区分から取得して実行マニフェストへ保存する。仕様上の固定件数を置かない。

### 利用条件上の注意
個人向けサービスには、利用者本人の利用、第三者提供、サブスクリプション終了後のデータ等に関する条件がある。短期契約で全履歴を取得して契約後も恒久利用する設計や、クラウドで第三者へデータを見せる設計は採用前に規約確認が必要である。本書は法的判断ではなく、実装時に最新規約と利用形態を照合するための設計上の注意である。

## 4. yfinanceの位置付け

### 確認事項
- 現行アプリが使用しており、低コストで長めの価格履歴を取得しやすい。
- yfinance自身がYahoo非公認のオープンソースで、研究・教育目的、Yahoo Financeデータは個人利用向けである旨を明記している。
- 価格調整の既定値や取得仕様はライブラリ版に依存する。現行requirements.txtは版を固定していない。

### 評価
yfinanceだけで、時点別母集団、上場廃止の網羅性、企業行動の完全性、再現可能な訂正履歴を保証できない。探索用プロバイダーとして既存資産を再利用できるが、正式評価の単独根拠にはしない。

yfinance/Yahoo側が日本株・ETFの対象件数、更新時刻、リクエスト上限、履歴保持を公式なサービス水準として公開していることは確認できなかった。実取得件数と欠損率をスナップショットごとに測定する。

資料:
- [yfinance公式リポジトリの利用上の注意](https://github.com/ranaroussi/yfinance)
- [yfinance download API](https://ranaroussi.github.io/yfinance/reference/api/yfinance.download.html)

## 5. JPX公開情報の補完利用

JPX公開情報は、現在の上場銘柄、直近1年の廃止銘柄を含む一覧、株式の廃止情報、ETF一覧・廃止情報の照合に使える。株式の廃止一覧ページは過去11年という掲載制約が明記されている。ETF一覧には分類や売買単位等があるが、過去時点の全属性履歴を一つの無料APIで得られるわけではない。

資料:
- [東証上場銘柄一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)
- [株式の上場廃止銘柄一覧](https://www.jpx.co.jp/listing/stocks/delisted/)
- [東証ETF一覧](https://www.jpx.co.jp/equities/products/etfs/issues/01.html)
- [ETF上場廃止一覧](https://www.jpx.co.jp/equities/products/etfs/delisting/)
- [JPxData Portal](https://www.jpx.co.jp/markets/data-catalog/)

## 6. データ契約（設計提案）

各レコードまたはスナップショットに次を保持する。

- provider、dataset、取得日時、対象日時、タイムゾーン
- raw/normalizedの別、スキーマ版、ファイルハッシュ
- raw OHLCV、調整係数、調整済み系列を別フィールドで管理
- 配当・分配金の権利落日、基準日、支払日、金額、訂正版
- 分割・併合等の基準日、効力発生日、比率
- 銘柄内部ID、コードの有効期間、上場・廃止、資産クラス、売買単位
- 欠損、重複、異常値、取得失敗、手動補正の理由

自動補完で不明値を埋めない。供給元間で価格や企業行動が違う場合は優先順位と差を記録する。

## 7. 提案する段階的方針

### 提案A: 完全無料の探索フェーズ
- 価格・アクション候補: yfinance
- 現在の分類・売買単位: JPX公開情報
- 過去母集団の部分検算: J-Quants FreeとJPX廃止一覧
- 出力には「サバイバーシップ、配当、廃止銘柄網羅性を保証しない」と表示

### 提案B: 正確性を優先する評価フェーズ
- 必要期間・配当の要件に合うJ-Quantsプランまたは別の許諾済みデータを継続利用
- 時点別マスター、企業行動、配当、売買単位を取得・照合
- 契約・保存・表示条件を満たすローカル運用

提案Aの結果だけで「オルカンを上回る戦略」と結論付けない。Bを採用しない場合、正式評価を完了できない可能性を受け入れる必要がある。
