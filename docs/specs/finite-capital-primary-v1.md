# 有限資金・仮想端数株による主検証方針 v1

2026年11月6日。版1.0。会話で合意した方向と提示済みの比較条件を、ローカルへの引き継ぎ用に保存する。**方針の保存であり、新方式の実装完了・検証実行済みを意味しない。**

## 目的と位置付け

検索画面と同じ条件でエントリー候補になった時点で買った場合に、有限の資金で資産を増やせたかを調べる。スイング運用を想定し、当面は日足。オルカンを80%持つという資産配分の前提は外し、戦略自体を評価する。

従来の資金上限なし・同一銘柄の重複ありの独立仮想取引は、入口・出口の補助診断として保持する。今後の主検証は有限資金ポートフォリオとし、独立取引の平均損益率をポートフォリオのCAGRと呼ばない。過去の結果や検索ページは削除しない。

## 会話で選択した主検証

| ID | 項目 | 方針 |
| --- | --- | --- |
| R-FC01 | 購入単位 | 主検証は仮想端数株。整数1株・100株単位の制約は設けない。SBIのS株とは区別する。 |
| R-FC02 | 資金 | 初期資金1,000万円、1回の購入枠10万円という整理を引き継ぐ。追加資金・レバレッジなし。 |
| R-FC03 | 購入額 | 株価を無視せず、購入時の価格と費用から端数を含む数量を算出する。購入枠は資産増加に比例させず固定する。 |
| R-FC04 | 保有中の再シグナル | 同一銘柄を保有中は追加購入しない。再シグナルで保有期限等もリセットしない。 |
| R-FC05 | ポジション数 | 別途の最大保有数を設けず、有限資金と購入枠で制約する。100銘柄を固定上限にしない。 |
| R-FC06 | 入口 | 検索機能の既存判定をそのまま共有する。パラメータ・計算式を変更しない。 |
| R-FC07 | 比較の目的 | 実運用50万円の制約を先に強く掛けるより、メソッドの性質を調べる。50万円・整数株・S株の再現は後段で区別する。 |

R-FC02の金額は会話で整理した基準値を記録したもの。ユーザーが明示選択した主検証の購入方式は「仮想端数株」。以下の細部や実運用の許容損失まで一括承認済みと解釈しない。

## 提示済みの運用細部：実装前に確認する基準案

- 10万円は購入手数料込みの枠とする。買いスリッページ反映後の価格をP、手数料率をcとすると、数量は100,000 / (P × (1+c))。枠に満たない残金での縮小購入はせず見送る。
- 利益は現金へ戻し、固定10万円の購入枠を増額しない。余力が増えれば保有できる件数が増える。待機現金の利息は0とする。
- 日足確定後の候補を翌営業日寄付で買う。寄付売却を先に処理し、その代金は同日の寄付購入に利用できる。日中の売却代金を、その日の寄付購入へ遡って使わない。
- 同時候補が余力を超える場合は、既存の銘柄コード順を比較の基準案とし、優先順位と見送り理由を保存する。最適な順位とは扱わない。
- 売却後は、売却後の確定足で元の検索条件が成立すれば次の寄付で再購入可能とする。売却前のシグナルは繰り越さない。
- RSI等の継続条件を独自に「falseからtrueになった日だけ」へ変えない。再購入条件と同日再購入の可否を実装前に明確化する。
- 既存と同じロングのみ、売買それぞれ手数料0.1%、スリッページ0.05%。価格ギャップ、日足内の価格到達順序、取引不可の扱いも既存仕様を確認して引き継ぐ。

## 入口と出口の比較範囲

入口は既存の7設定（TradingView添付版、Anti 3/10適応版、Anti 7/4/10版、初版試作、ミネルヴィニ派生、RSI2、RSI14）。共有関数は `linda_versions.evaluate_version`、`search.search_minervini`、`search.search_rsi`。バックテスト側は `backtest_signals.screening_signals` を通じて同じ判定を使う。

入口や出口の探索範囲を今回の保存作業で増やさない。[入口・出口診断仕様](entry-exit-diagnosis-v1.md)の既存比較を引き継ぐ。

- A/B/C/Dは保有期限なし。初期損切り3・5・8・10・12%。
- Aは初期ストップ、Bはそれに既存の反対候補・RSI回復・ミネルヴィニの10%トレーリング等を組み合わせる。
- C/Dの診断用基準幅Uは購入価格の8%固定、初期利確は24%。Cはストップのみ、Dはストップと利確を既存の規則で切り上げる。初期損切り幅を変えてもUは連動させない。
- 固定保有5・10・20・40・60営業日の独立評価は補助診断。有限資金の主成績と混ぜない。

1か月で必ず売却する、好調なら2〜3か月延長する、月次でOCOを更新する、資産全体の損失20%で停止するといった新条件は未採用。原典の公式出口として断定せず、既存の出口案として比較する。

## 対象と期間

[全市場検証方針](full-market-validation-v1.md)の公式一覧を固定した東証内国株式・国内上場ETFを継続する。代表50銘柄を全市場と呼ばない。現在の一覧には上場廃止銘柄を遡って含められないため、生存者バイアスを明記する。

| 比較期間 | 指標準備用データの開始年 |
| --- | --- |
| 2016年1月4日〜2020年12月30日 | 2014年 |
| 2021年1月4日〜2025年12月30日 | 2019年 |

両期間で同じ対象一覧を使用する。個別株とETFは成績を分ける。それぞれ同じ初期資金の独立ポートフォリオにするか、共通資金で別集計にするかは実装前に確認する基準案の一つであり、黙って変更しない。

オルカンとの比較は、同じ初期資金・評価開始終了日・通貨・評価基準を揃え、待機現金と未決済保有を含む純資産で行う。実ファンド設定日2018年10月31日より前を、実ファンドの実績として補完しない。2016年からの期間は戦略の頑健性確認に使い、代替指数を用いる場合は別途定義して実ファンドと区別する。

## 保存する評価項目

- 初期・期末純資産、総リターン、CAGR、最大ドローダウン、回復期間。現金と未決済保有を含める。
- 年別成績、資金稼働率、現金比率、最大保有数、余力不足・重複保有による見送り件数。
- 全取引、数量・価格・費用、発注根拠とシグナル日、保有推移、銘柄別損益寄与と利益集中度。
- 対象原本・取得日時・データ補正履歴・失敗／除外理由・全比較条件。最高成績だけ抜き出さない。

## 現在の実装との差とローカルでの次作業

文書保存時点の実装確認に基づく差分。実装済みと取り違えない。

| 現在の機能 | 今回の主検証との差 |
| --- | --- |
| `backtest.run_independent_backtest` | 同額の独立仮想取引。総資金制約がなく、同一銘柄の重複取引を許す。A〜D対応でも主検証の代用にならない。 |
| `backtest.run_backtest` | 最大5保有・資産比率20%・売買単位に丸める既定値。固定10万円の端数購入ではなく、出口もA/B対応。 |
| `market_research.py` の全市場分割処理 | 独立仮想取引の処理基盤。取得・再開機能があっても有限資金の全市場検証が完成した意味ではない。 |

ローカルでは、最初に最新コードと本書を読み、未決定の細部を確認する。その後に有限資金・固定購入枠・端数数量・重複防止・A〜Dの整合を実装する。既存CLIの `--evaluation portfolio` を指定するだけで本方針を満たすとは扱わない。

実データ実行の前に、少量の固定合成データで資金収支、費用込み枠、余力不足、同時候補、重複抑止、売却後再購入、売買順序、出口A〜D、期末時価評価、共有入口の一致を確認する。大規模取得・最適化・本検証はこの文書保存作業では実施しない。

## 未解決事項・実行の前提

- 上記「運用細部」の確定、個別株／ETFの資金分離、実運用の許容損失は未決定事項を含む。
- 2016〜2020年用データに追加の価格不整合・負価格がある。既存の補正承認を無制限に拡張せず、[データ品質仕様](backtest-data-quality-v1.md)のR-DQ05を守る。未承認補正を適用して本実行しない。
- クラウドではJPX公式一覧の取得が制限され、実際の全市場件数・全市場成績は未確認。ローカルで原本を固定してから対象確定する。
- 調整済み価格による仮想端数株の検証と、過去の名目価格・分割・配当・売買単位・S株の約定条件まで再現した実運用検証は区別する。整数1株へ丸めるだけでは実運用の再現にならない。
- 既存結果は探索・改善向けデータ。オルカン超過や将来の利益を保証せず、本方針の結果が既に得られたとも表示しない。
