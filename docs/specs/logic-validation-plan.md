# バックテスト前ロジック検証のテスト設計・実装計画

作成日: 2026-11-05 / 版: 1.0-approved / 状態: **実装承認済み・実行中**

## 1. 今回の境界

### 実施する

- 承認済みの `lbr_anti_stochastic_v1` と `lbr_anti_310_adaptation_v1` を純粋なPython関数として実装する。
- 指標計算、入力検証、Anti状態判定をStreamlitとデータ取得から分離する。
- setupとhook、その根拠となる中間状態を固定データで自動テストする。
- Streamlitから同じ共通ロジックを呼び、最新状態とチャートを可視化する。
- Linux/Python 3.11のクラウド環境でセットアップとテストを再現できる構成を用意する。

### 実施しない

- entry、exit、stop、注文、ポジション、損益を定義すること。
- 過去全期間のバックテスト、最適化、オルカン比較。
- 他戦略の未承認な数値条件。
- Streamlitデプロイ、外部公開、通知、実注文。

## 2. 実装単位

| 単位 | 責務 |
| --- | --- |
| `stock_screener/validation.py` | OHLC入力契約の検証 |
| `stock_screener/indicators.py` | SMA3/10/16と7/4/10の因果的な計算 |
| `stock_screener/anti.py` | 共通状態機械と2戦略の評価関数 |
| `app.py` | データ取得、設定、結果・中間値・チャートの表示 |
| `tests/` | 手計算値、境界、対称性、未来不変性、契約の検証 |
| `.devcontainer/`, `scripts/` | クラウドセットアップと検証コマンド |

テクニカル指標ライブラリは追加せず、pandasのrollingを使用する。

## 3. テスト順序

1. 入力契約と完全窓SMAの手計算値を固定する。
2. 3/10と7/4/10のウォームアップ位置、zero-range、欠損伝播を固定する。
3. 人工Fast/Slow系列で状態遷移、2/3本境界、接触・交差、Long/Short鏡像を固定する。
4. OHLC/Closeから指標と状態判定を通す統合テストを行う。
5. 将来行追加と将来値変更で過去出力が不変であることを確認する。
6. UIが共通評価関数だけを利用し、旧EMA/V字条件を含まないことを確認する。
7. Linux向けセットアップ、テスト、コンパイル確認を実行する。

詳細な数式、状態遷移、出力、境界条件は [lbr-anti-logic.md](lbr-anti-logic.md) を正本とする。

## 4. 実装順序

1. 仕様書とテスト期待値を固定する。
2. 入力検証と指標計算を実装する。
3. 共通Anti状態機械と2つの薄い評価関数を実装する。
4. 自動テストで独立検算する。
5. Streamlitを共通ロジックへ接続し、旧ロジックを削除する。
6. エラー、判定日、phase、setup/hook、中間値を画面へ反映する。
7. クラウド用セットアップと実行手順を検証する。
8. ロジック検証結果を提示して停止し、バックテストは明示依頼を待つ。

## 5. 完了条件

- 承認済み2戦略の数式と状態遷移が自動テストで固定されている。
- 指標式と状態遷移が承認済み仕様だけに従っている。
- 同じ評価関数をStreamlitと将来のバックテストから呼べる。
- setupとhookがentry/exitから明確に分離されている。
- データ不足、入力不正、取得失敗、単なる不成立を区別できる。
- 将来参照防止、Long/Short対称性、交差設定のテストが合格する。
- クラウドで再現するためのセットアップ・テスト・起動コマンドが文書化されている。
- バックテスト、損益比較、最適化を実行していない。
