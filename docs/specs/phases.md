# 開発フェーズ

更新日: 2026-11-05 / 版: 1.1 / 状態: **フェーズ2を承認済み・実行中**

各フェーズの承認は、その後のフェーズを自動承認しない。特にバックテストはユーザーから明示依頼があるまで開始しない。

## フェーズ0: 調査・要求整理（完了）

- リポジトリ、データ源、戦略候補、アーキテクチャを調査した。
- 要求、品質条件、未決定事項を `docs/specs/` に整理した。
- 重複したサブフォルダとプロンプトメモをユーザー承認のもと削除した。
- 旧Cline仕様はユーザー指示により削除し、互換対象にしない。

## フェーズ1: Anti仕様・テスト設計（承認済み）

- `lbr_anti_stochastic_v1` と `lbr_anti_310_adaptation_v1` を分離する。
- 指標、ウォームアップ、状態遷移、2/3本境界、接触・交差、欠損、未来不変性を仕様化する。
- setup/hookとentry/exitを分離する。

正本: [lbr-anti-logic.md](lbr-anti-logic.md)

## フェーズ2: バックテスト前ロジック検証（実行中）

- 共通の入力検証、指標、Anti状態機械を純粋Pythonへ実装する。
- 固定fixtureの自動テストで手計算値、境界、対称性、未来不変性を確認する。
- Streamlitから同じ共通ロジックを呼び、phase、setup、hook、中間値を可視化する。
- Linux/Python 3.11で再現できるクラウドセットアップを追加する。
- 作業ブランチをGitHubへpushし、クラウドCodexから取得可能にする。

完了条件は [logic-validation-plan.md](logic-validation-plan.md) に従う。バックテスト、損益、注文は対象外。

## フェーズ3: ユーザーによるロジック確認（未着手）

- 固定fixtureと実データの少数銘柄表示で、指標とsetup/hookを確認する。
- 誤りがあれば仕様へ戻って修正し、版を更新する。
- ロジック承認後も、売買規則とバックテストは別途承認する。

## フェーズ4: 売買・バックテスト詳細仕様（未承認）

- entry、stop、exit、注文時刻、約定、コスト、売買単位、資金配分を決める。
- データ源、企業行動、配当、時点別母集団、サバイバーシップバイアス対策を決める。
- IS/OOS、ウォークフォワード、評価指標、オルカン比較条件を決める。
- 詳細テスト設計と実装計画を作成し、ユーザー承認を待つ。

## フェーズ5: 最小バックテストエンジン（未承認）

- 日足イベント順、注文、約定、現金、保有、コストを実装する。
- 合成fixtureで会計保存則、企業行動、同時シグナル、資金不足、未来不変性を検証する。
- このフェーズ開始にはユーザーの明示依頼が必要である。

## フェーズ6: 評価・ベンチマーク（未承認）

- 日次資産とリターン・リスク・売買指標を集計する。
- オルカン公式基準価額を優先し、同一期間・円建て・同一キャッシュフローで比較する。
- 代替指数やETFを使う場合はproxyとして限界を表示する。

## フェーズ7: 他戦略を1つずつ追加（未承認）

- タートルズ、RS＋ブレイクアウト、Trend Template、VCPを個別の仕様承認後に追加する。
- 各戦略で仕様、テスト、実装、IS、凍結、OOSの順を守る。
- 一度に複数戦略を最適化しない。

## フェーズ8: ロバストネス・UI・運用（未承認）

- コスト・パラメータ・年度・相場局面・データ源への感応度を検証する。
- 保存済み結果をStreamlitでPC/iPhone向けに表示する。
- 通知、米国市場、デプロイはそれぞれ別仕様・別承認で追加する。FXはユーザーの2026年11月5日の指示により対象外とする。

## 停止条件

未承認のフェーズへ依存する機能は実装しない。データで確認できない条件を推測で補完しない。検証結果が弱い、または無料データに限界がある場合も、そのまま記録して次の判断をユーザーへ戻す。
