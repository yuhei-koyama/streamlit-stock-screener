# F02。全実行入口の休場日検証を共通化

2026年11月7日。ユーザーは2件目の修正案に「承認する（推奨）」と回答。対象は実行前の共通休場日検証と、その回帰テスト。

## 確定した修正範囲

通常バックテスト、入口・出口診断、追加期間検証、全市場バッチで、計算に渡す営業日カレンダー・約定入力・指標入力・RS参照を共通の規則で確認する。休場日を含む入力は計算前に停止し、原本を保持して営業日だけの入力へ再準備するよう案内する。

保存済み結果の参照と新規計算を区分する。カレンダー版を持たない旧入力も計算時には検査する。休場日を含まない旧形式は通常バックテストで利用可能とし、形式の変更だけを目的とした再準備は要求しない。

## 実装

- `trading_calendar.validate_execution_calendar`を共通の検査とする。既存の2014〜2025年向け規則を使用する。
- `load_dataset(..., for_execution=True)`を各実行入口で使用する。通常の参照読込は既存動作を保持する。新しいカレンダー版付き入力の履歴ハッシュも引き続き検証する。
- 通常バックテストはrun_suite経由で検証する。診断CLIと追加期間CLIでは、入力検証を出力ディレクトリ作成より前に行う。
- 全市場バッチは原本キャッシュから休場日を区分した後、指標計算前に同じ検査を通す。
- 通常のprepare_exploratoryも休場日を区分し、元のOHLCV・日付・銘柄・除外理由とハッシュを保存する。営業日の出来高ゼロは保持する。
- 価格補正の派生入力を作る処理では、既存の休場日除外履歴も引き継ぐ。価格補正の対象や規則はF02で追加しない。
- 結果には実行時のカレンダー版を記録し、通常バックテストの結果には入力側の休場日除外履歴も保存する。

## 検証

新規6件で、旧形式の参照、全CLIの実行前停止、通常2評価方式の指標計算前停止、各入力とRS参照の検査、休場日なし旧形式の計算、再準備・原本保持を検証する。実際の各CLIを子プロセスから起動し、休場日入力では出力先が作られないことを確認する。

実データの読込監査では、既存70銘柄の休場日なし入力と新しい50銘柄営業日入力が計算用検査を通過した。以前の197行補正のみの入力は参照可能で、計算時には休場日混入として停止した。監査した入力ファイルのハッシュは保持された。記録は`artifacts/review-f02-20261107/input_verification.json`。

例外的な全日停止のカレンダー追加F04や、承認済み価格補正一覧への照合F03は個別確認の対象として残す。
